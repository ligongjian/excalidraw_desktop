# Excalidraw 桌面版 · 性能优化总结

> 适用范围：Rust + Tauri 2 + React 18 + TypeScript + Vite 构建的桌面白板应用
> 更新日期：2026-09-26

本文档记录本项目已落地的性能优化手段与方法，说明每项手段的目标、做法、收益与涉及文件，并给出验证方式和后续可挖掘的方向。

---

## 一、优化目标

Excalidraw 是当前体积最大的第三方库（含完整编辑器 UI 与依赖）。首屏若整包同步加载，会让应用骨架的可用时间明显变长。优化目标是：

1. **缩短首屏可用时间**：优先渲染应用骨架（标题栏 / 标签栏 / 菜单 / 状态栏），画布按需后台加载。
2. **降低主入口 bundle 体积**：把体积大户拆分出去，按操作触发才加载。
3. **减少无效渲染与无效状态更新**：避免视图变化引发整树重渲或误判。

---

## 二、已落地的优化手段

### 1. 画布懒加载（React.lazy + Suspense）

- **目标**：Excalidraw 整体拆成独立 chunk，首屏不加载。
- **方法**：
  - 把画布实例抽成独立组件 `src/components/CanvasPane.tsx`，内部静态引用 `<Excalidraw>`。
  - `App.tsx` 中 `const CanvasPane = lazy(() => import("./components/CanvasPane"))`，渲染处用 `<Suspense fallback={<CanvasFallback/>}>` 包裹。
  - `CanvasFallback` 提供加载占位（转圈 + “正在加载画布…”）。
- **收益**：Excalidraw 及其依赖不再进入主入口 chunk，随画布需要才加载；配合启动画面在后台完成加载，过渡自然。
- **涉及文件**：新增 `src/components/CanvasPane.tsx`；修改 `src/App.tsx`。

### 2. 工具函数动态 import（按需加载）

- **目标**：`serializeAsJSON` / `restore` / `exportToBlob` / `exportToSvg` / `exportToClipboard` 这些导出/保存工具不再静态引入进首屏。
- **方法**：在各处理函数内改为 `const { xxx } = await import("@excalidraw/excalidraw")`，操作发生时才加载。模块一旦加载即被缓存，后续调用命中缓存、无额外开销。
- **收益**：主入口不再因顶层 `import` 而携带整个 Excalidraw 运行时。
- **涉及文件**：`src/App.tsx`（`handleOpen` / `handleSave` / `handleExport` / `handleExportSvg` / `handleExportPdf` / `handleCopyImage` / `handleCopyJson` / `saveDraft` / 草稿恢复 / 关闭拦截）。

### 3. “关于”对话框懒加载

- **目标**：微信二维码图片、对话框相关资源不进首屏。
- **方法**：`AboutDialog` 改为 `lazy`，并以 `{aboutOpen && <Suspense fallback={null}>…}` 条件挂载——点击“关于”才加载。
- **涉及文件**：`src/App.tsx`、`src/components/AboutDialog.tsx`。

### 4. 重依赖按需加载（jsPDF）

- **目标**：PDF 导出库不拖慢首屏与其他操作。
- **方法**：`const { jsPDF } = await import("jspdf")`，仅在“导出 PDF”时加载该 chunk。
- **涉及文件**：`src/App.tsx`（`handleExportPdf`）。

### 5. 模块级常量 + 类型窄化（as const）

- **目标**：避免每次渲染生成新对象导致 Excalidraw 重复渲染；满足 `UIOptions` 的窄类型约束。
- **方法**：`UI_OPTIONS` 定义为模块级 `const … as const`，让 `export/toggleTheme` 等保持字面量类型。
- **涉及文件**：`src/components/CanvasPane.tsx`。

### 6. 引用稳定化（useCallback / useRef / 模块级常量）

- **目标**：让传给 Excalidraw 的回调引用保持稳定，减少不必要重渲染。
- **方法**：`handleAPI` / `handleChange` 用 `useCallback` 包裹并固定依赖；实例统一存 `apisRef`，供保存/导出/主题同步读取；`UI_OPTIONS` 模块级常量化。
- **涉及文件**：`src/components/CanvasPane.tsx`、`src/App.tsx`。

### 7. 内容签名判定，最小化状态更新

- **目标**：选中、缩放、视口等“视图变化”不应触发“内容已修改”状态更新。
- **方法**：`elementsKey(elements) = id:version:versionNonce` 拼接，仅在内容签名偏离基线时才标脏（dirty）。
- **收益**：`onChange` 因视图变化高频触发时，不再无意义地更新 dirty 状态与整树。
- **涉及文件**：`src/App.tsx`（`elementsKey` / `handleChange`）。

### 8. 移除 StrictMode 双挂载

- **目标**：避免 mount → unmount → remount 导致场景注入被覆盖（既是修复也是性能/稳定性优化）。
- **方法**：`main.tsx` 用 `createRoot(...).render(<App/>)` 直接渲染，并删除多余的 `React` import。
- **涉及文件**：`src/main.tsx`。

### 9. 启动画面配合加载节奏

- **目标**：优化感知性能，避免加载空白与内容闪烁。
- **方法**：`SplashScreen` 覆盖层在首个画布实例就绪且至少显示 700ms 后淡出（3.5s 兜底），保证消失时画布已就绪。
- **涉及文件**：`src/components/SplashScreen.tsx`、`src/App.tsx`。

## 三、验证方式

1. **构建产物观察**：`npm run build` 后查看 `dist/assets/`，应出现独立 chunk（如 `CanvasPane-*.js`、`AboutDialog-*.js`、`jspdf-*.js`），主入口体积明显变小。
2. **运行时验证**：`npm run tauri dev`，观察启动画面期间后台加载画布；分别触发导出 PDF、打开“关于”，确认对应 chunk 按需加载（Network 面板）。
3. **类型校验**：`tsc --noEmit` 通过（`as const` 保证 `UIOptions.export: false` 满足 `false | ExportOpts` 窄类型）。

---

## 四、注意事项

- 动态 `import` 的目标模块一旦加载会进入缓存，重复调用无额外开销；不应为了“看起来更懒”而拆得过碎，避免过多请求往返。
- `React.lazy` 需要 `Suspense` 边界；首屏画布加载期间用占位组件兜底，避免空白。
- 改 `tauri.conf.json` / Rust 侧后需重启 Tauri 进程（如 `dragDropEnabled`、`data_dir` 等）。

## 五、后续可进一步挖掘的方向

| 方向 | 说明 |
|---|---|
| 量化测量 | 用 `vite --report`/构建统计对比优化前后主包体积与首屏时间，沉淀为回归基线 |
| 图片资源压缩 | `weixin.jpg` 等静态资源压缩/换格式，进一步降首屏 |
| WebView 缓存 | 静态资源 HTTP 缓存 / 预加载关键 chunk |
| 画布实例池化 | 多标签全部常驻 Excalidraw 实例内存开销较大，可评估“最近使用 + 懒销毁/重建”策略 |
| 减少依赖 | 评估是否需要完整 Excalidraw 编辑器 UI（若仅用绘图内核可裁剪） |
